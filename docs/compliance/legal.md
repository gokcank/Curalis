# Legal

## Purpose

This document defines the legal, regulatory, licensing, and compliance principles of Curalis.

Its purpose is to ensure that the application is developed responsibly while respecting applicable laws, user rights, and software licensing requirements.

This document is not legal advice.

Professional legal review may be required before public release.

---

# Principles

Curalis is developed according to the following principles:

- User ownership
- Privacy by Design
- Transparency
- Regulatory awareness
- Open-source compliance

---

# Medical Disclaimer

Curalis is a medication management application.

It is **not**:

- a medical device
- a diagnostic system
- a treatment recommendation system
- a prescription service

The application assists users in organizing medication-related information.

Users remain responsible for their own healthcare decisions.

---

# Medical Advice

Curalis never provides:

- diagnoses
- prescriptions
- dosage recommendations
- treatment recommendations
- emergency assessments

Medical decisions belong to qualified healthcare professionals.

---

# Data Ownership

Users retain ownership of all personal data created within the application.

Examples include:

- medications
- reminders
- notes
- inventory
- attachments
- history

The project does not claim ownership of user-generated content.

---

# Privacy Compliance

The architecture should remain compatible with applicable privacy regulations, including:

- GDPR
- KVKK

Future regional regulations may also be considered.

---

# Consent

Features involving personal data processing require explicit user consent where applicable.

Examples include:

- cloud synchronization
- analytics
- crash reporting
- AI integrations

Consent should be:

- informed
- specific
- reversible

---

# Third-Party Data

Medication information obtained from external providers remains subject to the provider's terms of use.

Provider licenses and attribution requirements should be respected.

---

# Open Source

All third-party dependencies must use licenses compatible with the project.

Before adding a dependency, verify:

- license type
- maintenance status
- redistribution requirements

---

# Copyright

Do not include copyrighted medical content without permission.

Official documentation should be referenced rather than copied where licensing prohibits redistribution.

---

# Trademarks

Medication brand names remain the property of their respective trademark owners.

Displaying a medication name does not imply affiliation or endorsement.

---

# AI Usage

AI-generated content should never be presented as verified medical information.

AI output must comply with the project's Medical Safety rules.

---

# Exported Data

Users should be able to export their own information.

Exported files belong entirely to the user.

---

# Data Deletion

Users should be able to permanently delete their personal data.

Deletion should remove all locally stored information associated with the deleted records whenever technically possible.

---

# Future Cloud Services

Future cloud services should clearly define:

- data ownership
- storage location
- retention policy
- deletion policy
- security responsibilities

---

# Regulatory Awareness

If future versions introduce features that may qualify the application as a regulated medical device in certain jurisdictions, the project should undergo an appropriate regulatory assessment before release.

---

# License

The project's software license should be documented separately.

All contributors must respect the project's chosen license.

---

# Changes

Legal requirements may evolve over time.

This document should be reviewed whenever major legal, privacy, or regulatory changes occur.
