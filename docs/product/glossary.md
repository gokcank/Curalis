# Glossary

## Purpose

This document defines the terminology used throughout the Curalis project.

Its purpose is to ensure that contributors, AI agents, and future maintainers use consistent language across documentation, code, and user interfaces.

Each term should have exactly one meaning within the project.

---

# General Terms

## Curalis

The medication management application described by this documentation.

---

## User

A person using Curalis to manage medications and related health information.

---

## Medication

A specific commercial pharmaceutical product used by the user.

Examples include branded and generic medications.

A medication may contain one or more active ingredients.

---

## Active Ingredient

The pharmacologically active substance contained within a medication.

Multiple medications may share the same active ingredient.

---

## Medication Record

A medication stored in the user's personal database.

A medication record may originate from:

- Manual entry
- External provider
- Future synchronization

---

## Manual Medication

A medication created entirely by the user.

Manual medications are first-class entities and support every feature available to imported medications.

---

## Imported Medication

A medication obtained from an external provider.

Imported medications may contain additional metadata supplied by trusted sources.

---

# Medication Management

## Treatment

A planned course of medication use.

A treatment may contain one or more medications.

---

## Reminder

A scheduled notification reminding the user to take medication.

A reminder never implies that medication was taken.

A reminder may generate one or more notifications.

---

## Notification

A platform-specific message generated by the application to deliver reminder or system information.

Notifications are a delivery mechanism and should not be confused with reminders.

---

## Reminder Schedule

The timing rules governing reminder generation.

Examples:

- Daily
- Weekly
- Monthly
- Interval
- As-needed (PRN)

---

## Reminder History

A record of reminder events over time.

Reminder history represents reminder activity, not medical outcomes.

---

## Medication Intake

A user-confirmed record indicating that medication was taken.

Medication intake always requires explicit user confirmation.

---

## Missed Reminder

A reminder that expired without user confirmation.

A missed reminder does not imply that medication was intentionally skipped.

---

## Skipped Medication

A reminder explicitly marked as skipped by the user.

---

## Snooze

A temporary postponement of a reminder.

Snoozing never changes the original reminder schedule.

---

# Inventory

## Inventory

The quantity of medication currently available to the user.

---

## Refill

The process of replenishing medication inventory.

---

## Low Inventory

A configurable threshold indicating that medication supply is becoming limited.

---

# Providers

## Provider

An external source of medication information.

Examples include public APIs and future custom backends.

Providers never own user data.

---

## Provider Data

Information obtained from external medication providers.

Provider data supplements user-owned information.

---

## Provider Cache

Locally stored copies of provider responses used to improve performance and reduce network requests.

---

# Architecture

## Local-First

An architectural principle in which the local database remains the primary source of truth.

The application must remain functional without internet connectivity.

---

## Synchronization

The process of exchanging user data between the local database and future cloud services.

Synchronization is optional.

---

## Repository

The abstraction responsible for coordinating data access.

Repositories decide where data originates.

---

## Use Case

A unit of application logic responsible for performing a specific business operation.

---

## Entity

A business object with a stable identity.

Examples include medications, reminders, and inventory records.

---

## Module

A logical group of related functionality within the application.

---

# Medical Safety

## Verified Information

Medical information originating from trusted providers.

Verification status should always be visible to the user.

---

## User Information

Medical information entered directly by the user.

User information should never be presented as verified provider information.

---

## Medical Advice

Recommendations regarding diagnosis, treatment, medication selection, or dosage.

Curalis never provides medical advice.

---

# Privacy & Security

## Sensitive Data

Information requiring enhanced protection.

Examples include:

- Medication history
- Notes
- Attachments
- Reminder history

---

## Personal Data

Information capable of identifying a specific individual.

---

## Consent

A clear and explicit user decision permitting a specific action.

Consent should be informed, reversible, and specific.

---

# User Interface

## Screen

A complete interface representing a single task or feature.

---

## Card

A reusable UI component used to display grouped information.

---

## Dialog

A temporary interface requiring user attention before continuing.

---

## Snackbar

A temporary message providing lightweight feedback.

---

## Empty State

A screen displayed when no relevant data exists.

An empty state should guide the user toward the next meaningful action.

---

# Development

## ADR

Architectural Decision Record.

A document describing a significant architectural decision and its rationale.

---

## Decision

A documented project decision that does not require an ADR.

---

## MVP

Minimum Viable Product.

The smallest feature set that delivers meaningful value to users.

---

## Source of Truth

The authoritative location where a specific type of information is maintained.

Each topic should have exactly one source of truth.

---

# Naming Conventions

The following terms should be preferred throughout the project:

| Preferred | Avoid |
|-----------|-------|
| Medication | Drug (when referring to user records) |
| Active Ingredient | Chemical |
| Reminder | Alarm |
| Inventory | Stock |
| Provider | API |
| Local Database | Local Storage |
| Synchronization | Sync (documentation) |
| Medication Intake | Confirmation |
| Manual Medication | Custom Medication |
